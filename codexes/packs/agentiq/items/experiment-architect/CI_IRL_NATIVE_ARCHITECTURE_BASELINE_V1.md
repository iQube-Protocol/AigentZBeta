## Purpose

Register the frozen Constitutional Internet × IRL native architecture baseline as an Experiment Architect resource without creating a second canonical copy.

Experiment Architect MUST consume the authoritative IRL source when designing the later CI × IRL × OCSGA boundary-validation experiment. This resource is an index/contract pointing to that frozen research artifact; it does not supersede, duplicate, normalize, or reinterpret it.

## Experiment-architecture role

The baseline supplies the pre-exchange architecture against which the independently produced OCSGA baseline will later be compared. It records CI and IRL/Constitutional Computing in their native terms before OCSGA-side exchange and preserves the distinction between discovered compatibility and created compatibility.

Experiment Architect should use it to:

1. preserve the frozen CI/IRL pre-exchange boundary;
2. compare it only after the independently frozen OCSGA map is received;
3. construct a neutral seam/boundary comparison matrix before proposing integration;
4. classify interfaces as COMPATIBLE / AMBIGUOUS / CONFLICTING / REDUNDANT / UNRESOLVED;
5. distinguish discovered compatibility from compatibility created through later redesign;
6. identify independently perturbable architectural seams for experimental design;
7. design falsification/ablation tests only after the boundary comparison is complete.

## Candidate experimental seam

The current CI/IRL candidate runtime chain may be used as a **test object**, not as an assumed OCSGA architecture:

`Governance → Authority + Mandate + Control conditions`

`Proposed Action + Current State + Consequence Projection + applicable bounds → Authorization`

`Authorization → Execution → Realized Consequence → Evidence → Updated State / Trust`

The later comparison must determine whether OCSGA exposes independently compatible interfaces to any of these objects rather than assigning them to OCSGA in advance.

## Research principle

> **Preserve independent boundaries first. Test the seams second. Co-design only where evidence establishes a genuine gap.**

And:

> **Discovering compatibility is evidence about the systems as they are. Creating compatibility is evidence about what the systems can become together.**

## Gate to experiment design

Experiment Architect should not promote this work into a joint CI × IRL × OCSGA experiment until:

- the OCSGA native map exists independently;
- both maps have frozen/versioned provenance;
- the maps have been compared without silent terminology normalization;
- interface classifications have been recorded;
- unresolved ownership/semantic conflicts are visible;
- the proposed experiment can state whether it tests native compatibility or a deliberately co-designed interface.

Only then should Experiment Architect define perturbations, controls, observables, falsification criteria, evidence requirements, and experimental execution architecture.
