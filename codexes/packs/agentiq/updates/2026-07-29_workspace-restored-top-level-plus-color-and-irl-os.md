# Workspace restored to top level + colour accent + IRL OS mirror

**Date:** 2026-07-29
**Branch:** `claude/tokenqube-minting-integration-ms2yjd`
**Corrects/amends:** `codexes/packs/agentiq/updates/2026-07-29_participation-workspace-nav-restructure.md` (that document's own history is left unedited — this is a forward correction, the same pattern earlier docs this session used for "RESOLVED"/superseded annotations rather than rewrites).

## Why this exists

The immediately-prior change (`259b563`, recorded in the doc above) folded the IRL cartridge's Research Workspace into a single "Workspace" tab nested inside Participation, with the workspace's own seven former top-level views pushed one tier deeper into that tab's `subTabs` — three tiers end to end (top group → Workspace tab among Participation's other tabs → its subTabs). The operator tried the shipped result: **"the triple menu system is looking messy."** This change corrects the nesting depth while keeping everything else 259b563 got right.

## What changed

1. **Workspace is a top-level tabGroup again** — a sibling of Institution / Research / Laboratory / Publications / Participation, sited **immediately after Participation** (`order: 5`, Participation is `order: 4`) — "logical place after request for participation then the user gets access to the workspace." It is no longer filed under `group: 'participation'`.
2. **The fix is minimal by design.** The `irl-workspace` tab object is unchanged in every field except `group` (now `'workspace'`) and `order` (now `0`, the sole tab in its own group). Its `subTabs` array — the seven offered views (Locker/Participants stay pruned, per the operator's own 259b563 instruction) plus the Tier-0 Administration view — is untouched. Because `irl-workspace` is the ONLY tab in the new `workspace` group, `CodexPanelDynamic` renders it through the same **"single-tab group with subTabs"** path already used for "Order of Metayé" (see the literal comment at `app/triad/components/CodexPanelDynamic.tsx` around the tier-2/tier-3 row logic) — the subTabs render inline on the breadcrumb row instead of requiring an extra tab-selection step. A caller clicks "Workspace" once and lands directly on Overview/Pipeline/Review/etc. That is the same two-tier shape every other top-level cartridge tab in this system already has.
3. **`buildResearchWorkspaceTab(idPrefix)`** — a new shared function in `data/codex-configs.ts` (top of file, near the `RESEARCH_WORKSPACE_VIEWS` import) replaces the hand-authored tab-object literal. It builds the full Workspace tab (metadata, subTabs derived from `RESEARCH_WORKSPACE_VIEWS`, the Tier-0 view) parameterised only by an id/slug prefix, so `IRL_CARTRIDGE` and `IRL_OS_CARTRIDGE` both call the SAME function rather than each carrying a hand-copied object (`inv.engineering.037` — a parallel implementation of an existing capability is a defect). A `workspaceSlugSuffix()` helper strips the registry's baked-in `irl-workspace-` slug prefix and re-applies the caller's own prefix, so `IRL_CARTRIDGE`'s ids/slugs are byte-identical to before (e.g. `irl-workspace-overview`, `irl-workspace-materials`) and `IRL_OS_CARTRIDGE` gets its own non-colliding namespace (`irl-os-workspace-overview`, etc.).
4. **Workspace added to `IRL_OS_CARTRIDGE`** — "workspace should also be added to the IRL OS cartridge — that's really the main place it's going to live, but it can be in both IRL OS and the IRL cartridges." Same `workspace` tabGroup shape, same `LayoutGrid` icon, positioned the same way (immediately after Participation), built by the identical `buildResearchWorkspaceTab('irl-os-workspace')` call — a registry-level addition, not a second implementation.
5. **The vertical, section-grouped programme nav is kept** (Autonomi / Lehigh / MFE Capstone / CS Capstone) — untouched in shape. The `LayoutGrid`/`Compass` icon distinction from 259b563 is also kept.
6. **The left nav now genuinely matches the Laboratory → Experiments sidebar's structural behaviour**, not just its look (`components/composer/InvariantExperimentLab.tsx` is the reference):
   - Same collapsing-rail classes: `overflow-y-auto rounded-xl border border-slate-800 bg-slate-900/40 backdrop-blur-sm transition-all duration-200`, toggling `w-56` ↔ `w-8`.
   - Same collapsed-state shape: a vertical icon-only strip (all items flattened, section grouping dropped) with a `ChevronRight` expand button — identical to the Laboratory sidebar's own collapsed rail.
   - Same expanded-state shape: a header row (title + `ChevronLeft` collapse button), then `space-y-3` sections, each `space-y-1` items, each label wrapped in `<span className="truncate">`.
   - The colour accent and inline-rename affordance are additive on top of this shape — the base scroll/collapse/truncate mechanics are unchanged from the reference.
   - The surrounding `PartnerProgrammesTab` root (research kind only) now wraps in `flex h-full … overflow-hidden` with the content column as `overflow-y-auto`, the same bounded/independently-scrolling shape `InvariantExperimentLab`'s own top-level wrapper uses — not just matching classNames on the nav in isolation. The venture kind's layout is untouched (`flex gap-4 p-4`, unchanged).
7. **A restrained colour accent, reusing existing tokens.** The operator: *"it's all a bit monochromatic... use some colour... just to break up the monotony... not too much, just some accents and tones"* — scoped to the Programme Command Center's metric cards and the Overview subsection headers beneath it, nowhere else.
   - **Reused, not invented:** the four accent hex values are the exact `field.*` tokens from the AgentiQ Liquid Glass representation interpretation (`services/representation/interpretations/agentiqLiquidGlass.ts`) — `field.reasoning` (`#818CF8`, indigo), `field.knowledge` (`#C084FC`, purple), `field.consequence` (`#FBBF24`, amber), `field.intelligence` (`#38BDF8`, sky). That file's own comment already describes this set as the platform's "bright, maximally separable hues... for distinguishing categorical sectors" — exactly the job the four left-nav sections need.
   - `PartnerProgrammesTab.tsx` is not representation-adopted (no `RepresentationProvider` / `var(--rep-*)` CSS variables here), so the hex values are read directly as constants (`FIELD_ACCENT`, `NAV_SECTION_ACCENT`) rather than through the CSS-variable path an adopted surface would use — a scoped, deliberate exception to the slate house style (CLAUDE.md "Canonical Surface Styling"), not a departure from it elsewhere.
   - `NAV_SECTION_ACCENT` maps each of the four left-nav sections to one of those hexes: Autonomi → reasoning (indigo), Lehigh → knowledge (purple), MFE Capstone → consequence (amber), CS Capstone → intelligence (sky).
   - `commandAccent` (research kind only, `null` for venture) resolves the ACTIVE workspace's section colour and threads into: (a) every `MetricCard` in the Programme Command Center, rendered as a 2px coloured top hairline + a ~7% alpha background wash (never a solid fill), and (b) a small `AccentDot` beside the Objectives/Layer Owners/Contacts subsection headings under Overview, plus a matching 2px left-border accent on those panels.
   - The left nav's own section-header styling (slate, uppercase, no colour) is deliberately left untouched, to preserve pixel/structural parity with the Laboratory sidebar per point 6 above — the colour lives on the Command Center and its subsections only, exactly where the operator asked for it.
