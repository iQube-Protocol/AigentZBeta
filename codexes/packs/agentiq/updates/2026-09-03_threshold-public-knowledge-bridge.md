# Threshold MCP Bridge — public knowledge & discovery layer

**Date:** 2026-09-03
**Scope:** Threshold MCP Bridge (`services/threshold/gateway.ts`, `app/api/threshold/mcp/route.ts`) — new public, read-only knowledge/discovery layer spanning Qriptopian, IRL OS, AgentiQ OS, and Polity Core.

## What shipped

Five new unauthenticated MCP tools (`list_public_cartridges`, `list_public_documents`, `read_public_document`, `search_public_knowledge`, `list_public_capabilities`), one new resource (`metame://public-knowledge`), and one new prompt (`explore_public_knowledge`), backed by a new adapter `services/threshold/publicKnowledge.ts`. Shared the resilient-fetch helper with `irlAdapter.ts` via a new `services/threshold/resilientFetch.ts` extraction (no forked duplicate).

## Cartridge identity resolution (per-cartridge audit, no guessing)

- **Qriptopian** → `qripto-codex` / slug `qripto`. Content spans two independent stores: `codex_media_assets` (papers/magazines, discriminated by `series_scope`) and `content` (Thresholds essays, `domain='qriptopian'` + tags). Reused the LIVE public routes (`/api/codex/qripto/papers`, `/api/codex/qripto/essays`, `/api/codex/qripto/essays/:slug/machine`) rather than a parallel Supabase query path.
- **IRL OS** → `irl-os-cartridge` / slug `irl-os`, distinct from the private `irl-cartridge` (metaMe IRL workspace). The `foundation/` pack corpus is a CONFIRMED MIXED public/confidential corpus per `docs/security/2026-08-27_irl-os-containment-breach-audit.md` — only `foundation/PARTICIPATION_overview.md` is allowlisted public. Delegated entirely to the EXISTING `IrlAdapter` (`ctx.irl`), adding no new IRL read path.
- **AgentiQ OS** → `agentiq-os-cartridge` / slug `agentiq-os`. Resolved as a genuinely separate, intentional cartridge from the private `agentiq-codex` engineering KB — no active dual-source collision today (the historical 2026-05-26 incident CLAUDE.md warns about is already reverted/documented). Allowlisted the 16 `codexes/packs/agentiq-os/items/*.md` guides plus the 7-file `col_capabilities` (Constitutional Capability Briefs) subset of the separately-packed `agentiq/updates/` stream. Explicitly EXCLUDED the rest of that 474-file `updates/` directory, which the cartridge's own non-gated "Updates" tab otherwise resolves to — a real, previously-unflagged exposure risk found during this audit.
- **Polity Core** → `polity-core-cartridge` / slug `polity-core`. Allowlisted 23 documents across the 15 non-`adminOnly` tabs (verified against `data/codex-configs.ts` + `collections.json`), tagged with each document's own self-declared status (`ratified` / `explanatory` / `proposed` / `historical`) verified by reading every file's own header line — never inferred. Excluded the one `adminOnly` tab (`polity-core-commentary-constitutional-internet`, the working-manuscript book project) and everything under `items/commentary/constitutional-internet/**`.

## Access control

Default-deny, allowlist-only for AgentiQ OS and Polity Core (no directory scan, no caller-supplied path ever reaches `corpusReadPackFile`). IRL OS reuses the already-audited public routes unchanged. Qriptopian reuses the live, already-public REST routes. No document/content-level publication-status field exists yet for three of the four cartridges (confirmed by direct audit) — an allowlist was the only sound posture available; widening any cartridge's allowlist requires the same operator classification review as this one, never inferred from a tab's `enabled` flag, a domain string, or an "active" status.

**Confirmed live** (against the running dev server, `?tab=` etc.): a non-allowlisted id (e.g. a constitutional-internet path) is refused before `corpusReadPackFile` is ever called; a real allowlisted document (`polity-core`/`constitution`) returns actual full text with correct offset/limit/hasMore pagination and a `sha256OfFullText` that reconstructs correctly across pages.
