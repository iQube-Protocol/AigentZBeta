## Body

Audit found HIGH_CONFIDENCE_THRESHOLD=95 has no calibration or governance
ratification anywhere in the repo, and observed machine confidence tops
out around 90% — the control was structurally unreachable. Confidence in
both provenanceSuggestion.ts and relationshipSuggestion.ts is an
identical LLM self-report (0-100), never a measured probability.

Removes the dead "Accept All High-Confidence (>95%)" batch button from
both Stage 5 (ClassificationQueue) and Stage 7 (RelationshipQueue).
Mirrors the existing Stage 5 ProvenanceCohortRatificationBoard pattern
for Stage 7: new relationshipCohortPreparation.ts service + relationship-
cohort API route + RelationshipCohortRatificationBoard, primary CTA reads
"Ratify relationship cohort — add N relationship(s)" (a real derived
count, never a bare percentage). Confidence still shown per-item as
supporting context, never as the write gate. contradicts edges and
cycle-creating suggestions are still never auto-accepted regardless of
confidence.

EXP-P1 scientific thresholds, crystalCohortMembership.ts,
populationReconciliation.ts, remediation profile, namespace boundaries
and exception-isolation semantics are untouched.
