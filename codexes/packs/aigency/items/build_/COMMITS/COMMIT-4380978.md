Restore metaMe IRL admin access, IRL OS Participation Overview, and IRL OS Workspace (scoped restoration)

Narrowly scoped fix built on deployed commit c1be210 (Phase 1 + addendum
containment), not a rollback. Root causes fixed:

1. AgentiqCartridgeTab used a raw, unauthenticated fetch() against the
   irl-pack-gated /api/codex/packs/[packId]/file route, which requires a
   Bearer token via getActivePersona -> getCallerIdentityContext. Every
   caller, including genuinely authenticated admins, therefore 403'd on
   collections.json -- the confirmed root cause of "Failed to load
   collections for irl" across metaMe IRL. Fixed by switching both fetch
   calls to personaFetch (utils/personaSpine), which attaches the caller's
   Bearer token when one exists and is a no-op passthrough otherwise.

2. The same component always fetched the full collections.json listing
   before ever attempting a defaultPath document, and a failed listing
   fetch hard-blocked rendering even when the specific document was itself
   independently allowlisted. Fixed with a graceful-degradation fallback:
   on a collections-fetch failure with defaultPath set, synthesize a
   single-item collection from the caller-declared prop (never from server
   data) so the content effect can still attempt the one document read.
   Restores IRL OS Participation Overview for public (unauthenticated)
   visitors without exposing the private collection catalogue.

3. IRL OS's Workspace tab (irl-os-workspace) shared PartnerProgrammesTab's
   DeepLinkCard rendering with metaMe IRL's own Workspace tab, which
   constructed live irl-cartridge deep links -- the original breach vector,
   disabled by the emergency containment pass. Restored with a new
   render-boundary guard instead of reactivating the vector:
   forbiddenCodexSlugs on PartnerProgrammesTabProps, threaded through every
   AreaLinks call site, drops any DeepLinkCard whose codexSlug is on the
   list -- for that mount only. buildResearchWorkspaceTab passes
   forbiddenCodexSlugs: ['irl-cartridge'] for every irl-os- mount and leaves
   the private irl-cartridge mount's own self-links untouched. The
   BoundaryResearchProgressPanel "Explore IRL OS" link and the OCSGA
   Bridge's irl-exchange-workspace Full View affordance are both repointed
   back at irl-os-workspace now that it is safe.

Access model unchanged and verified, not modified: grantedScopes/
scopesGrantedIn still cohort-isolates which workspace a caller may even
see; a public/ungranted visitor lands on the existing generic empty state,
never a workspace list. Query-derived isAdmin/personaId authority remains
removed (2026-08-27 addendum, untouched by this pass).

IRL_CARTRIDGE's own tab registry required no changes -- diffed against the
pre-incident parent (a772be507) and confirmed unaffected apart from the
now-inert forbiddenCodexSlugs: undefined default on its own Workspace
mount.
